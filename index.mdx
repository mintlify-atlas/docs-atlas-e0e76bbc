EDA Agent gives you a structured foundation for building autonomous agents that communicate entirely through events. Instead of tight coupling between components, every action is expressed as an event — published to a central bus, routed to the right handlers, and processed asynchronously. The result is a system that scales naturally and stays easy to reason about.

## How It Works

EDA Agent centres on three primitives: the **Agent**, the **EventBus**, and **EventHandlers**. The agent coordinates its own lifecycle; the bus moves events between producers and consumers; handlers contain your business logic.

<Steps>
  <Step title="Define your events">
    Declare typed event objects that represent every meaningful action in your system — a user signing up, a task completing, a sensor reading arriving.
  </Step>
  <Step title="Register handlers">
    Subscribe handler functions to specific event types. Each handler receives the full event payload and can publish new events in response.
  </Step>
  <Step title="Start the agent">
    Call `agent.start()` to boot the event bus and begin processing. The agent listens for events, dispatches them to the correct handlers, and manages graceful shutdown.
  </Step>
  <Step title="Publish events">
    Emit events from anywhere in your application. The bus routes them to all registered subscribers automatically.
  </Step>
</Steps>

## Key Features

<CardGroup cols={2}>
  <Card title="Asynchronous by Default" icon="bolt">
    Events are processed asynchronously, keeping producers decoupled from consumer latency.
  </Card>
  <Card title="Typed Event Contracts" icon="file-contract">
    Define strict schemas for every event type to catch integration errors at development time.
  </Card>
  <Card title="Composable Handlers" icon="puzzle-piece">
    Handlers are plain functions — easy to test, combine, and reuse across multiple event types.
  </Card>
  <Card title="Graceful Lifecycle" icon="circle-check">
    Built-in `start()` and `stop()` hooks let the agent drain in-flight events before shutting down.
  </Card>
</CardGroup>
